## Нефункциональные

**Изоляция и безопасность**

- N1. Лапп не может вызвать back другого лаппа, прочитать его ассеты, данные или хранилище WebView.
- N2. Команды управления платформой доступны только окну лаунчера.
- N3. Back получает только возможности по выданным разрешениям; по умолчанию — ничего, кроме
  минимального WASI без доступа к ФС и сети.
- N4. Распаковка архивов защищена от выхода за каталог лаппа (zip-slip) и не перезаписывает
  существующее.
- N5. Секреты (ключи подписи, пароли keystore) не попадают в репозиторий и логи.

**Надёжность**

- N6. Ошибка, паника или trap одного лаппа не роняет платформу и другие лаппы; команды возвращают
  ошибку, а не паникуют.
- N7. Вызов back-а ограничен по времени (настраиваемо) и по памяти.
- N8. Медленный лапп не блокирует UI и другие лаппы: Tauri-команды не выполняются в главном потоке,
  лаппы исполняются параллельно.

**Local-first**

- N9. Все функции платформы и примеров, кроме сетевых (HTTP, P2P), работают без сети.
- N10. Данные пользователя и лаппов хранятся в каталогах, которыми владеет пользователь, и
  переживают обновление платформы.

**Производительность и размер**

- N11. Release-сборки фронтов оптимизируются (`wasm-release`, `wasm-opt -Oz`); компиляция back-ов —
  один раз на загрузку, без повторной на каждый запрос.

**Сопровождение**

- N12. Сборка — через `cargo-make`; CI — `cargo make lint` и `cargo make test`, тесты покрывают
  настройки, реестр, разрешения и исполнение эталонного back-а.
- N13. Стиль: Rust 2024, nightly rustfmt по `.rustfmt.toml`, `taplo` для TOML, зависимости через
  `[workspace.dependencies]`.

## Вне рамок MVP

- HTTP-сервер для доступа к лаппам из внешнего браузера/по локальной сети с access token и TLS
  (так работал прежний Laplace) — возможен позже как отдельный режим.
- Процесс на лапп на Android и выгрузка лаппов при нехватке памяти
  (`issues/deferred/26-08-04 android kill lapp.md`).
- Сборка под iOS, самообновление, интеграция с Lamark, обход NAT в P2P.
