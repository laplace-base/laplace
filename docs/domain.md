# Предметная область

## Понятия

**Laplace (платформа)** — приложение на устройстве пользователя, которое хранит, запускает и
изолирует лаппы и даёт им доступ к ресурсам устройства и сети в пределах выданных разрешений.

**Лапп (lapp)** — изолированное local-first веб-приложение, исполняемое платформой. Состоит из:

- **front** — интерфейс, работающий в окне (WebView) платформы;
- **back** — логика и доступ к данным, WASI-компонент в рантайме платформы. Back необязателен:
  лапп может быть чисто клиентским (таков сам лаунчер);
- **манифест** `config.toml` — метаданные, требуемые разрешения и настройки ресурсов;
- **каталог данных** — личные данные лаппа на устройстве (по умолчанию `data`).

**Имя лаппа** — идентификатор: имя каталога лаппа, метка его окна, префикс его API
(`/<name>/api/...`). Уникально в пределах платформы.

**Лаунчер** — встроенный лапп `laplace`: список лаппов, их включение, разрешения, установка. В список
лаппов сам не входит. **vendor** — псевдо-лапп с общими веб-ассетами (htmx, стили wingy).

**Окно лаппа** — у лаппа не больше одного окна; повторное открытие поднимает существующее. На Android
окно — отдельная задача в списке недавних.

**Разрешение (permission)** — право лаппа на класс операций. Манифест перечисляет **требуемые**
(`required`) разрешения, пользователь решает, какие из них **выданы** (`allowed`). Действие без
выданного разрешения отклоняется. Набор, унаследованный от прежней версии:

| Разрешение | Смысл |
| --- | --- |
| `client_http` | фронт может обращаться к своему back-у (в новом манифесте echo — `invoke_back`) |
| `file_read`, `file_write` | чтение / изменение каталога данных лаппа |
| `database` | своя SQLite-база |
| `http` | исходящие HTTP-запросы (с фильтром методов и хостов из `network.http`) |
| `websocket` | двусторонний канал back ↔ front (push) |
| `tcp` | сетевые соединения, в т.ч. P2P (`network.gossipsub`) |
| `sleep` | приостановка исполнения back-а |
| `lapps_incoming`, `lapps_outgoing` | запросы между лаппами (`lapp_requests`) — пока не реализованы нигде |

**Включён (enabled)** — лапп можно открывать и вызывать; выключенный лапп установлен, но не
исполняется. **Автозагрузка (autoload)** — back включённого лаппа инстанцируется при старте
платформы, иначе — лениво, при первом обращении.

**Инстанс** — загруженный и инициализированный back лаппа (`Store` + экземпляр компонента).
Перезапускается при изменении разрешений или настроек работающего лаппа.

**Архив лаппа (`.lar`)** — zip с файлами лаппа; имя архива задаёт имя лаппа. Установка не затирает
существующий лапп.

**Пир, gossipsub** — участник P2P-сети лаппа и протокол рассылки сообщений между пирами (libp2p) с
обнаружением в локальной сети через mDNS.

**Каталог данных платформы** — на десктопе это каталог рядом с `Laplace.toml`, на Android —
`Documents/Laplace` в общем хранилище. Принадлежит пользователю: платформа не удаляет из него файлы
и не перезаписывает его правки без явной настройки.

**Lamark** — будущий сервис-каталог лаппов, из которого платформа сможет их устанавливать.

## Жизненный цикл лаппа

```
 установлен ──► включён ──► инстанцирован ──► окно открыто
     ▲   │          │  ▲         │   ▲             │
     │   ▼          ▼  │         ▼   │             ▼
  удалён       выключен    остановлен / перезапущен (смена разрешений, сбой, таймаут)
```

- **Установка** — копирование файлов лаппа в каталоги платформы (сборкой, распаковкой APK или из
  `.lar`) и регистрация его манифеста.
- **Включение/выключение, автозагрузка, выдача/отзыв разрешений** — правка манифеста из лаунчера с
  сохранением в `config.toml`.
- **Инстанцирование** — при старте (autoload) или при первом запросе; инициализация back-а
  (например, создание таблиц) выполняется один раз на инстанс, её ошибка делает лапп недоступным,
  но не платформу.
- **Сбой** back-а (trap, паника, превышение времени) завершает только этот инстанс.

## Инварианты

1. Имя лаппа = имя каталога = метка окна; у лаппа одно окно.
2. Фронт лаппа обращается только к своему back-у; чужие ассеты и чужие back-и ему недоступны.
3. Back получает только те возможности хоста, разрешения на которые выданы.
4. Управлять платформой (список лаппов, настройки, установка) может только лаунчер.
5. Данные пользователя не покидают устройство, кроме как через выданные лаппу сетевые разрешения.
