Этап 3.3 плана миграции (`26-10-01 migration plan.md`). Опирается на контекст инстанса (`InstanceContext`, 3.1; хосты back-а добавить в него здесь) и на способ отказа без права, выбранный в 3.2.

Сейчас back не может сделать ни одного сетевого запроса. При этом настройки уже есть:
- манифест просит хосты, методы и тайм-аут — `[required.network.http.back]` (`BackHttpSettings`);
- пользователь выбирает хосты — `[allowed.network.http.back]`;
- действующие хосты считает `LappUserSettings::effective_http_hosts().back`, с учётом права `http` back-а.

Back — место для запросов с сессией и cookie и к сайтам без CORS: у фронта cookie внешних сайтов общие для всех лаппов, а CORS режет ответы (`docs/architecture.md`, «Внешние запросы фронта»).

Что сделать:

- **Протокол — `wasi:http`.** Стандартный `wasi:http/outgoing-handler` через `wasmtime-wasi-http` (версия в пару к `wasmtime` 49), а не свой импорт поверх `reqwest`, как в старом. Причины:
  - back собирается под `wasm32-wasip2`, где `wasi:http` — часть платформы;
  - для клиента в SDK есть готовые привязки (`wasip2` уже в `Cargo.lock`);
  - проверку можно встроить в `WasiHttpView::send_request`.

  Своего интерфейса в `wit/` не добавляется. Записать решение в план, убрав его из «открытых решений».
- **Хост.**
  - `wasmtime_wasi_http::add_only_http_to_linker_sync` в общий `Linker`.
  - `WasiStates` реализует `WasiHttpView`: свой `WasiHttpCtx` и `ResourceTable`, общий с WASI.
  - `send_request` перед отправкой проверяет:
    - право `http` back-а по контексту инстанса;
    - хост запроса по действующим хостам: точное имя, `*.` — поддомены, `all`. Порт — частью хоста, как в CSP фронта;
    - метод по `required.network.http.back.methods`;
    - схему: `https`, а `http` — только для явно указанного хоста.

    Отказ — `ErrorCode::HttpRequestDenied`.
  - Тайм-ауты — из `timeout_ms` манифеста (`OutgoingRequestConfig`: соединение, первый байт, между байтами). Дедлайн по эпохам блокирующее ожидание сети не прерывает (26-11-15), так что тайм-аут запроса обязателен.
- **Локальная сеть.** Запросы к loopback, частным и link-local адресам (`127.0.0.0/8`, `::1`, `10/8`, `172.16/12`, `192.168/16`, `169.254/16`, `fc00::/7`, `fe80::/10`) и к `localhost` — только если хост указан в списке явно, а не через `all` или `*.`. Хост-литерал IP проверяется сразу. Имя, которое разрешается в частный адрес (DNS rebinding), — проверить, даёт ли `wasmtime-wasi-http` подменить резолв или соединение. Если нет — записать ограничение в `docs/architecture.md` и в план.
- **`HttpMethod`** (`crates/settings/src/lapp.rs`) знает только `get`/`post` — дополнить `put`, `delete`, `patch`, `head`, `options`. Разбор манифеста с ними — тест.
- **SDK.** `laplace_back_api::http_client::send(http::Request<Vec<u8>>) -> Result<http::Response<Vec<u8>>, Error>` поверх `wasi:http` (через крейт `wasip2` или свои привязки в `generate!`), с ошибкой, по которой видно отказ хоста. Блокирующий вызов, без async.
- **Тестовый сервер.** Тесты не ходят в интернет. Локальный HTTP-сервер в тесте на `127.0.0.1` со случайным портом (`std::net::TcpListener` с ручным ответом, без новых зависимостей) — он же проверяет правило про loopback: разрешён только при явном `127.0.0.1:<port>` в хостах.
- **Документация.** `docs/architecture.md` (возможности back-а, внешние запросы), `docs/domain.md` (право `http` back-а), план (3.3), `AGENTS.md` при необходимости.

 Хост ( crates/app/src/outgoing.rs ). Перед отправкой каждого запроса хост проверяет:

   • Право. У back-а должно быть право  http .
   • Метод. Метод должен быть в манифесте.  HttpMethod  теперь знает  get ,  head ,  post ,  put ,  delete ,  patch ,  options .
   • Хост. Хост должен быть среди действующих хостов back-а:
     •  host  без порта разрешает только порт схемы по умолчанию;
     •  host:port  — только этот порт;
     •  *.domain  — только поддомены;
     •  all  — любой хост, кроме локальных.
   • Схема и локальные адреса. Обычный  http ,  localhost  и локальные адреса (loopback, частные сети, link-local и т. п.) разрешены, только если хост указан в списке как есть. Имя, пропущенное через  *.  или  
     all , хост сначала разрешает сам и отказывает, если среди адресов есть локальный.
   • Тайм-ауты. Тайм-ауты соединения, первого байта и пауз ограничены  timeout_ms  манифеста.

 При отказе back получает  HttpRequestDenied , а в лог хоста пишется предупреждение с причиной.

 SDK.  laplace_back_api::http_client::send  — блокирующий клиент поверх крейта  wasip2 .  Error::is_denied  отличает отказ хоста от сетевой ошибки.

 Тесты.

   • Юнит-тесты правил: хосты, порты, поддомены, право, методы, локальные адреса, тайм-ауты.
   • Тест разбора методов в манифесте.
   • Четыре интеграционных теста со stress (новый маршрут  /fetch?url=… ) и локальным сервером на  127.0.0.1 :
     • без права — отказ;
     • явно указанный  127.0.0.1:<port>  — ответ сервера, а другой порт и  POST  — отказ;
     • при  all  — отказ для loopback и  localhost ;

 Что нужно учитывать:

   • Тайм-аут запроса и дедлайн вызова. Тест с молчащим сервером показал: если  timeout_ms  запроса не меньше  lapps.call_timeout_ms , back падает по дедлайну вызова ( LappError::Timeout ) раньше, чем запрос
