Каталог лаппов на Android нужно вынести из песочницы приложения в общее хранилище, так чтобы он:

- был доступен для записи извне — пользователю через файловый менеджер, ПК по USB (MTP), другим
  приложениям через SAF;
- не исчезал при удалении Laplace.

Дополнительно, в перспективе сами лаппы должны уметь читать и писать любые пользовательские файлы
на устройстве. Разрешения на это выдаёт пользователь внутри самого Laplace, в рамках его системы
разграничения доступа, — а значит доступ ко всему пользовательскому хранилищу должен быть у
Laplace как у приложения.

Реализацией занимаемся отдельной задачей; ниже — разбор того, что для этого даёт Android.

## Каталог

Нынешний `Android/data/org.laplace/files` (`Context.getExternalFilesDir`) не подходит по обоим
критериям: он стирается при удалении приложения и на Android 11+ не виден ни другим приложениям,
ни файловым менеджерам. Нужен каталог на общем томе: файлы там переживают удаление приложения
(система чистит только app-specific каталоги), видны по MTP, доступны из файловых менеджеров и
выбираются через SAF.

Из `/sdcard/Laplace/` и `/sdcard/Documents/Laplace/` предпочтительнее второй. Свой каталог в корне
тома можно создать только при уже выданном `MANAGE_EXTERNAL_STORAGE`, а внутрь `Documents`
приложение может писать и без него — через MediaStore с `RELATIVE_PATH = "Documents/Laplace"`. То
есть на `Documents/Laplace` можно опереться и до того, как пользователь выдал разрешение. Плюс это
стандартная коллекция, её индексирует MediaStore, поэтому содержимое сразу видно по MTP (после
записи по обычному пути имеет смысл дёргать `MediaScannerConnection.scanFile`, иначе в индексе
файл появится не сразу).

«Доступен для записи внешним приложениям» здесь значит ровно то, что даёт Android: писать туда
сможет пользователь и приложения, у которых либо есть свой широкий доступ, либо им выдан SAF-доступ
на эту папку. Отдельного «сделать папку публично-записываемой» в Android нет — POSIX-права на общем
томе эмулируются и не настраиваются.

## Полный доступ к хранилищу

`MANAGE_EXTERNAL_STORAGE` («Доступ ко всем файлам», API 30+) — не runtime-разрешение, обычным
диалогом его не запросить:

- в манифест — `<uses-permission android:name="android.permission.MANAGE_EXTERNAL_STORAGE" />`;
- на старте проверять `Environment.isExternalStorageManager()`;
- если не выдано — отправлять пользователя интентом
  `ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION` с `package:org.laplace` в системные настройки.

Что даёт: чтение и запись всего общего хранилища обычными путями — работает `std::fs`, а значит и
`preopened_dir` у wasmtime. Это принципиально: лаппы исполняются как WASI-компоненты, и выдавать им
доступ естественно через preopen-каталоги, а preopen требует настоящего пути.

Чего не даёт даже будучи выданным: чужих `Android/data/<pkg>` и `Android/obb/<pkg>`, внутренних
данных других приложений (`/data/data/...`) и всего, что вне общих томов. «Доступ ко всему» на
Android — это доступ ко всему пользовательскому хранилищу, не к системе.

Разрешение пользователь может в любой момент отозвать, а спящие приложения система умеет сбрасывать,
поэтому `isExternalStorageManager()` надо проверять на каждом старте, а не один раз при установке.

Для API 24–29 нужна отдельная ветка: `READ_EXTERNAL_STORAGE` / `WRITE_EXTERNAL_STORAGE` (второе с
`android:maxSdkVersion="29"`) плюс runtime-запрос, а на API 29 ещё
`android:requestLegacyExternalStorage="true"`, иначе там включится scoped storage.

## Ограничение дистрибуции и план Б

Google Play пускает `MANAGE_EXTERNAL_STORAGE` только для приложений, чья основная функция — работа
с файлами (файловые менеджеры, бэкап, антивирусы, документооборот), и требует отдельной декларации
в консоли; «платформа для запуска приложений» — не гарантированно проходящая формулировка. При
распространении сайдлоадом или через F-Droid вопрос не стоит.

План Б — `ACTION_OPEN_DOCUMENT_TREE`: пользователь сам выбирает корень (в 11+ нельзя выбрать корень
основного тома, `Download` и `Android/data`, но `Documents/Laplace` — можно), доступ делается
persistable и переживает перезагрузку и обновление, но не переустановку. Цена: всё превращается в
`content://`, `std::fs` их не открывает, и под WASI пришлось бы писать свою реализацию
`wasi:filesystem` поверх `ContentResolver` вместо cap-std — заметно больше работы, чем preopen
реального каталога. Разумный компромисс — поддержать оба режима: по путям, когда «Доступ ко всем
файлам» выдан, и через SAF-дерево, когда нет.

## Что придётся поменять в нынешнем коде

- Распаковка ассетов (`crates/app/src/android.rs`) сейчас всегда перезаписывает файлы. Как только
  каталог переезжает в общее хранилище и переживает удаление приложения, эта политика затрёт то,
  что пользователь или лапп там поменяли. Нужен маркер версии на лапп (распаковывать из APK только
  при отсутствии или при росте версии) либо копирование только недостающего.
- `Laplace.toml` логично перенести туда же — тогда его можно править с телефона, не пересобирая APK.
- Fallback на нынешний `getExternalFilesDir()` стоит сохранить, чтобы приложение оставалось
  работоспособным, пока разрешение не выдано.
- Выдача лаппу доступа к каталогу — это `preopened_dir` в `WasiStates` (`crates/app/src/wasi.rs`),
  которого сейчас нет вовсе: у компонентов нет ни одного preopen. Система разграничения доступа
  Laplace ложится на `permissions` из `LappSettings` (`crates/settings`), которые хост пока не
  читает.

● Готово. Каталог лаппов переехал в общее хранилище, доступ запрашивается у пользователя,
  распаковка больше не затирает чужое. Проверено на эмуляторе (Android 31, x86_64).

  Что сделано

  - `crates/app/src/android.rs`: вместо `unpack_data_assets` теперь `prepare_data_dir`, который сам
    выбирает каталог данных и наполняет его из ассетов пакета. Результат — `DataDir` с путём,
    признаком `shared`, счётчиками распакованного и списком предупреждений (логгер к этому моменту
    ещё не поднят, поэтому предупреждения возвращаются наверх и пишутся уже после его инициализации).
  - Каталог данных — `Documents/Laplace` на общем хранилище
    (`Environment.getExternalStoragePublicDirectory(DIRECTORY_DOCUMENTS)`). Если доступа нет,
    приложение открывает экран его выдачи и на этот запуск использует прежний
    `Android/data/org.laplace/files/data`, который не требует разрешений вовсе.
  - Проверка доступа: на API 30+ — `Environment.isExternalStorageManager()`, ниже —
    `Context.checkSelfPermission(WRITE_EXTERNAL_STORAGE)`. Экран выдачи, соответственно,
    `ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION` или `ACTION_APPLICATION_DETAILS_SETTINGS`
    с `package:`-URI. Рантайм-диалог не используется: `requestPermissions` требует главного потока и
    колбэка в активити, а мы работаем из потока точки входа — экран настроек одинаково годится для
    обоих случаев.
  - Манифест: `MANAGE_EXTERNAL_STORAGE`, `READ_EXTERNAL_STORAGE` (`maxSdkVersion="32"`),
    `WRITE_EXTERNAL_STORAGE` (`maxSdkVersion="29"`), `android:requestLegacyExternalStorage="true"`.
  - Политика распаковки. Отсутствующий файл пишется всегда; существующий перезаписывается только
    если пакет переустанавливали или обновляли с прошлой распаковки (`PackageInfo.lastUpdateTime`,
    запоминается в `.unpacked` в каталоге данных); `Laplace.toml` не перезаписывается никогда —
    после первой распаковки он принадлежит пользователю. Ничего не удаляется, так что добавленные
    пользователем лаппы не трогаются. Обычный перезапуск не копирует ничего.
  - Записанные файлы отдаются `MediaScannerConnection.scanFile` — без этого они не попадают в
    `MediaStore` и не видны по MTP.
  - `run_mobile` берёт конфиг через `DataDir::config_path()` и логирует, какой каталог выбран,
    сколько распаковано и предупреждения.

  Проверено на эмуляторе

  | Сценарий | Результат |
  | --- | --- |
  | Первый запуск без доступа | `sandbox data directory '/storage/emulated/0/Android/data/org.laplace/files/data', unpacked 68 files`, открылся `Settings$AppManageExternalStorageActivity`, в логе предупреждение |
  | После `appops set ... MANAGE_EXTERNAL_STORAGE allow` и перезапуска | `shared data directory '/storage/emulated/0/Documents/Laplace', unpacked 68 files` |
  | Второй запуск | `unpacked 0 files` — штамп совпал |
  | Удалили `lapps/front/echo/main.css`, дописали строку в `Laplace.toml`, перезапуск | `unpacked 1 files`, css восстановлен, правка конфига на месте |
  | Испортили `main.css`, переустановили APK | `unpacked 67 files` (все, кроме `Laplace.toml`), css вернулся к оригиналу, правка конфига цела |
  | `MediaStore` | `content query` по `content://media/external/file` находит `Documents/Laplace/**` |
  | Удаление приложения | `Documents/Laplace` остался с правкой пользователя, `Android/data/org.laplace` система стёрла |
  | Сквозной сценарий | список приложений → Echo → `handle_http` → `echo-back.wasm` из `Documents/Laplace` → ответ в UI |

  Осталось за рамками

  - Доступ лаппов к файлам (preopen-каталоги в `WasiStates`, чтение `permissions` из `LappSettings`,
    UI выдачи прав) — это следующая задача; сейчас у компонентов по-прежнему нет ни одного preopen.
  - Пока доступ не выдан, экран настроек открывается на каждом запуске, а выданный доступ
    подхватывается только со следующего старта — перечитывать его на `onResume` не стали.
  - Ограничение Google Play на `MANAGE_EXTERNAL_STORAGE` в силе: для публикации в Play понадобится
    декларация или режим с SAF-деревом.
