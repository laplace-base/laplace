Доработка исходящего HTTP back-а (3.3): доступ к подсетям, к локальной сети пользователя и к loopback. Опирается на записи хостов из `26-11-23 http host entries.md`.

Сейчас локальный адрес — loopback, частные сети, link-local, ULA и т. п. (`is_local_ip`, `crates/app/src/outgoing.rs`) — доступен только по записи, указанной как есть: `192.168.1.10:8080`, `localhost:3000`. Через `*.` и `all` локальные адреса отклоняются. Подсети записать нельзя. Лаппу, который ищет устройства в сети, нужен диапазон адресов, а автор не знает сети пользователя.

Решения, принятые до задачи:
- локальная сеть и подсети — один вид записи `network`, без отдельного флага «`all` плюс локальные адреса»: пользователь, которому это нужно, добавляет запись `lan`;
- loopback — отдельно от `lan`;
- пользователь сужает сеть и методы, а добавляет свои записи только при `user_hosts = true` манифеста (26-11-23).

Что сделать:

- **Запись `network`** — третий вид `HttpHostEntry`, только у back-а:
  ```toml
  # манифест: лаппу нужна локальная сеть пользователя
  hosts = [{ network = "lan", ports = [80, 8080], methods = ["get"] }]

  # решение пользователя: только своя подсеть
  hosts = [{ network = "192.168.1.0/24" }]
  ```
  - **Значение `network`** — CIDR (IPv4 или IPv6) или ключевое слово:
    - `lan` — частные `10/8`, `172.16/12`, `192.168/16`, link-local `169.254/16` и `fe80::/10`, ULA `fc00::/7`;
    - `loopback` — `127.0.0.0/8` и `::1`.

    `lan` включает и `100.64/10` (решено): это и CGNAT провайдера, и адреса оверлейных сетей вроде Tailscale.
  - **`ports`** — список портов. Без него — любой порт.
  - **`methods`** — как у записи хоста.
  - Разбор CIDR — без новой зависимости, если это укладывается в небольшую функцию над `std::net`. Иначе — крейт `ipnet` (версия не моложе недели) через `[workspace.dependencies]`.
- **Фронт.** Запись `network` в `network.http.front` — ошибка разбора манифеста: CSP не выражает диапазоны адресов.
- **Совпадение.**
  - Запись `network` совпадает только с IP-литералом в URL: `http://192.168.1.20:8080/`. Имя, которое разрешается в эту сеть, не совпадает. Иначе получается тот же DNS rebinding: проверили один адрес, соединились с другим.
  - Порт сверяется с `ports`.
  - Запись `network` разрешает адрес, локальный он или нет. Плюс разрешает plain `http`: устройства в сети редко отвечают по `https`. Записать это в `docs/architecture.md`.
  - **Близость.** Явный хост, затем `network` с более длинным префиксом, затем маски и `all`. Если IP-литерал совпал с явной записью хоста, решает она.
  - **Без записи `network`.** Правила для `*.` и `all` не меняются: локальные адреса и имена, которые в них разрешаются, по-прежнему отклоняются.
  - **Loopback** доступен только по явной записи хоста или по `network = "loopback"` / CIDR внутри `127.0.0.0/8` и `::1`. `lan` его не включает.
- **Манифест и пользователь.**
  - Запись пользователя `network` действует, если её сеть лежит внутри сети записи манифеста: `192.168.1.0/24` внутри `lan`. Тогда её порты — подмножество портов манифеста, а методы сужаются так же, как в 26-11-23.
  - Сеть вне манифеста, в том числе `lan` и `loopback`, пользователь добавляет только при `user_hosts = true`.
  - `"all"` пользователя записей `network` из манифеста не добавляет сверх того, что манифест просит: это все записи манифеста, как в 26-11-23.
- **Поиск устройств — не только HTTP.** mDNS и сканирование портов — UDP и TCP, это этап 5 (право `tcp`). Записать в `docs/architecture.md`, что запись `network` покрывает только устройства с веб-интерфейсом.
- **Документация.** `docs/architecture.md` (исходящий HTTP back-а), `docs/domain.md` (право `http` back-а), план (3.3; этап 5 — ссылка на `network`).

Готово, когда:

- юнит-тесты `laplace-settings`:
  - разбор `network` — CIDR v4/v6, `lan`, `loopback`, `ports`;
  - ошибка для фронта и для неверного CIDR;
  - сеть пользователя внутри и вне сети манифеста, с `user_hosts` и без, сужение портов и методов;
- юнит-тесты `outgoing`:
  - IP внутри и вне сети, порт;
  - имя, разрешающееся в сеть, не совпадает;
  - `lan` не пускает к loopback, а `loopback` пускает;
  - близость: явный хост против сети, длинный префикс против короткого;
  - plain `http` по записи `network`;
- интеграционный тест со stress и локальным сервером на `127.0.0.1`:
  - `network = "loopback"` с портом сервера — ответ;
  - `network = "lan"` — отказ;
  - запись пользователя вне сети манифеста без `user_hosts` — отказ;
- `cargo make lint` и `cargo make test` проходят.

Сделано:

- `crates/settings/src/lapp/network.rs`: `IpNet` (CIDR v4/v6 без новой зависимости, адрес без префикса —
  сам адрес; IPv4-mapped IPv6 — как IPv4), `Network` — `Lan` (с `100.64/10`), `Loopback`, `Net`;
  `matches(ip)` — длина префикса диапазона, `contains(network)` — вложенность.
- `HostEntry { target: HostTarget, methods }`, `HostTarget::Host` или `Network { network, ports }`;
  разбор строки или таблицы (`host` или `network`, `ports` только у `network`); у фронта `network` —
  `LappSettingsError::Invalid`.
- `EffectiveHosts::resolve`: сеть пользователя — внутри сети манифеста и среди её портов (без своих
  портов берёт порты манифеста), иначе только при `user_hosts`.
- `outgoing`: `HostMatch::Network(префикс)` между масками и явным хостом; только IP-литерал и порт из
