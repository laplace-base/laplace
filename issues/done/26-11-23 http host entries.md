Доработка исходящего HTTP (3.3, `26-11-22 back outgoing http.md`) и CSP фронта (`26-11-13`): запись хоста со своими методами, выбор самой близкой записи, хосты, добавленные пользователем.

Сейчас:
- `HttpHosts` (`crates/settings/src/lapp.rs`) — это `"all"` или список строк. Методы — одни на всю секцию `[required.network.http.back] methods`.
- Действующие хосты — пересечение манифеста и решения пользователя (`HttpHosts::allowed_by`, `LappUserSettings::effective_http_hosts`). Выйти за манифест пользователь может, только если манифест просит `"all"`.
- `HttpAccess::host_match` (`crates/app/src/outgoing.rs`) различает только `Exact` и `Broad`. Методы проверяются по общему списку (`HttpMethods::allows`).

Решения, принятые до задачи:
- методы задаются для каждой записи; пользователь может их сужать, но не расширять;
- пользователь добавляет хосты, которых нет в манифесте, только если автор это разрешил (`user_hosts = true`);
- loopback и подсети — отдельная задача `26-11-24 http networks.md`; здесь формат записей должен позволить добавить вид `network`.

Что сделать:

- **Запись хоста** (`HttpHostEntry`). Строка, как сейчас, или таблица:
  ```toml
  [required.network.http.back]
  methods = ["get"]                  # для записей без своих методов
  user_hosts = true                  # пользователь может добавлять хосты
  hosts = [
    "api.example.org",
    { host = "upload.example.org", methods = ["post", "put"] },
  ]
  ```
  `"all"` и списки строк разбираются как раньше, тесты существующих манифестов не меняются. Ключ записи — `host` (`host`, `host:port`, `*.domain`), сравнивается без учёта регистра.
- **Манифест и пользователь.**
  - Решение пользователя — тот же формат: `[allowed.network.http.back] hosts = ["api.example.org", { host = "upload.example.org", methods = ["post"] }]`.
  - Действующая запись — запись пользователя с тем же ключом, что в манифесте. Её методы — пересечение методов манифеста (своих у записи или общих `methods`) и методов пользователя (без них — все методы манифеста).
  - Запись пользователя, которой нет в манифесте, действует только при `user_hosts = true`, с общими методами манифеста, сужаемыми так же.
  - `"all"` пользователя — все записи манифеста, но не «любые хосты».
  - `hosts = "all"` в манифесте — то же, что `user_hosts = true` плюс право пользователя выбрать `"all"`. Так сохраняется нынешнее поведение `allowed_by`.
  - Тип действующих хостов — список записей с итоговыми методами. `HttpAccess` получает его вместо пары `hosts` + `methods`.
- **Самая близкая запись.** Порядок: явный хост, затем маска с более длинным доменом, затем `all`. Методы проверяются по ней. Ограничения для `Broad` (plain `http`, локальные адреса, разрешение имени) остаются как есть: они зависят от вида совпадения, а не от методов.
- **Фронт.**
  - Запись с `methods` в `network.http.front` — ошибка разбора манифеста (`LappSettingsError`) с понятным текстом, а не молчаливое игнорирование: CSP методы не ограничивает.
  - `user_hosts` для фронта работает так же: добавленный пользователем хост попадает в CSP (`csp::policy`). Проверка `is_valid_host` применяется и к хостам пользователя.
- **`UpdateQuery`** записи хостов пока не меняет — это 6.2. В плане, пункт 6.2, уточнить: выдача и отзыв записи хоста и сужение её методов.
- **Документация.** `docs/architecture.md` («Внешние запросы фронта» и исходящий HTTP back-а), `docs/domain.md` (права `http`), план (3.3 и 6.2).

Готово, когда:

- тесты `laplace-settings`:
  - разбор строк, таблиц, `"all"` и смешанных списков;
  - `methods` у фронта — ошибка;
  - действующие записи: пересечение методов, сужение пользователем, запись пользователя вне манифеста — с `user_hosts` и без, `"all"` пользователя и манифеста;
- юнит-тесты `outgoing`: самая близкая запись решает (явный хост против маски, длинная маска против короткой, маска против `all`), методы берутся из неё;
- юнит-тест `csp`: хост пользователя при `user_hosts` попадает в политику, без отметки — нет;
- интеграционный тест со stress: запись с `methods = ["post"]` пропускает `POST` и отклоняет `GET`, а запись пользователя, сузившая методы, отклоняет метод манифеста;
